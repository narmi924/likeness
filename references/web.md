# 放进网页

访客滚动鼠标，片子跟着前进或后退。不是播放视频：每一帧都要能立刻到达，往回也一样。

## 得到什么

```text
likeness web tmp/film tmp/site walk.json --scene walk.blend
likeness serve tmp/site
```

```text
site/
  index.html   一个能直接用的播放页
  film.mjs     播放器：取片段、解码、画到画布上
  walk.mjs     不依赖浏览器的部分：镜头投影、滚动手感、清晰度选择
  film/
    film.json  每一帧的镜头、停靠点、可点击物的位置、每档清晰度里每一帧的字节数
    1440/ 1080/ 720/ 540/   每秒一个 .h264 文件
```

浏览器不能直接双击 `index.html` 播放，必须通过 `likeness serve` 或正式的网站地址。

## 为什么这样编码

- **每秒一个文件**：访客走到哪取到哪，不用下载整条。
- **每五分之一秒一个完整画面**（60 帧的片子每 12 帧一个），没有向后参考的帧：这样往前往后拖都能很快到达任意一帧。
- **用浏览器的视频解码接口（WebCodecs）逐帧解码**，画到 WebGL 画布上。普通的 `<video>` 标签拖动时会卡、往回放更差。
- **四档清晰度**，每档有码率上限（1440p 24、1080p 14、720p 7、540p 4 Mbit/s），树叶多的画面也不会超过访客的网速。

## 手感

这些数值都是在真实页面上反复试过、改过的，直接用，不要重新发明：

- **滚动是欠账，不是拖拽。** 滚轮每一格不直接把片子推出去，而是记成“欠多少秒”，片子按稳定的速度把它走完：平常 1 倍速，滚得猛 2 到 3 倍，停手后顺着滑约半秒。直接跟滚轮走会一冲一停，看起来像卡顿，其实解码没问题。
- 滚轮一格的量：`deltaY × 0.0042` 秒。触摸拖动：每像素 0.02 秒。方向键和翻页键：1 秒。空格：自动游览。
- 点停靠点的圆点直接快速过去，中间的片段不取、不解码。
- 屏幕刷新稳定时，每次刷新正好前进整数帧，不重复也不跳帧。

## 首次打开和清晰度

- **宁可多等几秒，不要走起来卡。** 显示之前先取好开头 6 秒；走的时候始终提前取 8 秒，最多 3 段同时取。只提前取 1 秒时，第一圈稍慢一点就断。
- **自动清晰度从窗口大小起步**：1080p 的窗口一开始就取 1080p。只有自己测到按正常速度走时画面跟不上，才降一档，并且让失败的那一档休息一会儿，免得来回跳。
- 浏览器自己报的网速太粗，不要用它来压清晰度。只有访客明确开了省流量或在 2G/3G 上才从低档起步。
- 升档只在停下来的时候做，走着的时候换档要重新取当前位置，会断。
- 访客手动选的一档一直保持，不会自动升降。

## 叠在片子上的东西

播放器每次刷新都会把当前帧的镜头和画面里的可点击物交给页面（`frame` 回调，以及页面上的 `walkframe` 事件）。

- **可点击的东西**：路线文件的 `spots` 里列出场景里的平面物体，`likeness web` 会读出它们四个角的位置写进 `film.json`。播放器把四个角投到屏幕上，`player.hit(x, y)` 返回鼠标下的那个。默认只有正面能点；太远（默认 45 米外）或者几乎侧对镜头时不算。地址后加 `?debug` 会用绿框画出来，用它核对点击范围和画面是否逐帧对得上。
- **贴在板上的文字**：把一个网页元素用 `quadMatrix(宽, 高, 四个角)` 变形贴到片子里的板上（`walk.mjs`）。片子里的板渲成空白，字由网页画，这样能换语言、能点、能打字。
- **雪、雨、沙**：在片子上面叠一层画布实时画。强度按位置写在 `film.json` 里（`likeness web --extra` 可以加自己的字段）。实时画的好处是停下来还在下、往回滚不会倒着飘。地面的积雪、水洼、远处的雨雾渲在片子里。
- **声音**：跟着人在哪个地方走，不跟时间走，往回滚也切回去。两地之间交叉渐变 3 秒；离开再回来从上次停的位置接着放。

现成的两层：`scripts/web/weather.mjs` 把雪、雨、贴地的沙画在播放画布上方，粒子停在空气里，人走或转身时它们往反方向滑；每一帧的雪、雨、沙浓度放在 film.json 里（`likeness web --extra`）。`scripts/web/sound.mjs` 按人所在的那一段放音乐、交叉渐变，风声现场生成，雨声用一段录音循环。用法写在两个文件开头。

## 声音的大小

- 音乐文件统一到 −18 LUFS，播放音量 0.45；环境声按同样的比例。
- 判断够不够响，拿普通网页视频来比。那次最初沿用旧网站的音量，结果电脑开到最大都听不清，整体提了约 20 分贝。
- 曲子开头如果有几秒几乎无声，从有声音的地方开始放，否则访客以为没有声音。

## 界面

- 画面上不放说明文字和带一堆字的按钮。
- 第一帧屏幕中间偏下一个滚轮在动的鼠标图标和“向下滚动”，3 秒后或一滚动就淡出。
- 自动游览是一个小小的文字按钮“自动 / Auto”。不用播放图标，访客会以为是放音乐。声音是一个喇叭图标。
- 地名和停靠点的圆点平时隐藏，换地方或鼠标动的时候淡入，3 秒后淡出。
- 清晰度菜单平时只显示当前档；点开后每档标出走完一圈的流量，后面不加解释。

`index.html` 已经做了前四条（它没有声音和清晰度菜单），接进正式网站时照着它来。

## 接进一个真实的网站

- 把 `film.mjs` 和 `walk.mjs` 当工具模块复制进项目，页面组件照 `index.html` 里的脚本写。
- 选了 3D 才加载播放器和片子；手机或不支持的浏览器给另一个首页。
- 片子不放进代码仓库。放对象存储，配自己的域名、跨域许可和长期缓存。Cloudflare R2 这类按流量不收费的存储合适。
- **已发布的版本目录永远不改。** 换片子是上传一个新目录，再改代码里的版本号。
- 本地开发从项目里一个不进仓库的文件夹读片子。
- 画面出错（显卡上下文丢失、取不到片段）时给一个“重试”，不要留一张冻住的图。

## 上线前在页面里查

```text
likeness page shot "http://127.0.0.1:8765/?debug" tmp/page.png --run "walk.go(12)" --wait 6
likeness page record "http://127.0.0.1:8765/" tmp/page.mp4 --seconds 12 --run "walk.setAuto(true)"
```

- 自动走一圈，`?debug` 里的 `gaps` 应该是 0（画面跟不上的次数）。
- 每个停靠点截一张，绿框和画面里的东西对得上。
- 向前猛滚、向后滚、点圆点跳转，各试一次。
- 无界面的 Chrome 测不出真实网速下的表现，也测不了 Safari 和 iPad。这两样要在真机和正式地址上看，并且明说没验证过的部分。
