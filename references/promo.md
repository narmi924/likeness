# 宣传片：从已经做好的场景里再拍一支

网站首页那条绕湖的片子做完以后，要给它做一支 30 秒左右的宣传片：开场在画板上问网站的 AI 一句，然后飞一圈经过四个地方，最后回到开场的画面。第一版是别人拿网站上的视频加工出来的，叠影、发软、对话框发飘；第二版回到 Blender 重新拍，画面干净，镜头卡在音乐的落点上。这一篇记两版的差别和第二版的做法。成品和全部脚本在作者本机的 `examples/promo/`，不随 skill 分享。

## 先认清：成品是离线渲染的片子，宣传片就回原场景重拍

已经渲好的片子只有一条固定路线、一个固定高度、一种速度。拿它去做宣传片，镜头怎么动都只能在 2D 里硬做，第一版的毛病全出在这里：

| 想要的 | 2D 加工的做法 | 看起来 |
|---|---|---|
| 飞得快 | 每秒 3 米的散步快进 7 倍，再把相邻几帧平均当运动模糊 | 一格一格的叠影 |
| 推近画板 | 把画面放大约 1.8 倍裁出来 | 发软 |
| 画板上的对话 | 网页截图平贴在画面上 | 比四周亮一截、比画板大一圈；背景在漂、框不动，看起来在飘 |
| 清晰度 | 用网页那套压缩过的分段，1080p 和 1440p 在片中来回换 | 树叶糊 |

场景还在（建场景的脚本、素材、布局数据都留着），重建只要几分钟，所以第一步就该是新写一条镜头路线、重新渲染。只要有 `.blend` 或能重建它的脚本，就不要碰成片的像素。

## 镜头：先找音乐的落点，再排路线

1. 先分析音乐：每 20 毫秒的响度找到落点（那首歌在 16.47 秒），自相关求拍长（0.49 秒）。起飞放在落点上，经过每个地方的时刻放在落点之后的整拍上（第 4、11、17、22 拍），回到开场画面也在整拍上。
2. 路线用沿路的里程 `s(t)` 写，关键点给出位置和速度，用 Hermite 插值：经过一个地方时 1.2 秒内保持每秒 8 米、侧头看它，之间自动加速，那次最快约每秒 55 米。朝向、俯仰、焦距、离岸距离、高度各自一条曲线，关键点在经过时刻前后。
3. 经过各地时直接用原片那几个停靠点的朝向、焦距和镜头上移，那些构图已经被认可过。
4. 侧倾按飞行方向本身转弯的快慢算（不按镜头朝向，否则侧头看的时候也会歪），速度高于每秒 12 米才加，最多 7 度，再做 0.5 秒平滑。
5. 离岸距离和高度：贴着路的内侧、离地约 2 米。整个世界是围着视平线那条路建的，飞高会看到没建的地方。擦着树冠穿过去的几下效果好，像无人机穿梭，不用全部躲开。
6. 起飞前先后退半步再转身，否则镜头会贴着画板擦过去。

那次的脚本是 `examples/promo/promo_path.py`（只在作者本机，不随 skill 分享）。它写出的每帧数据和原片的格式一样，多了 `roll`。

## 画板上的对话：真组件、真回答，当贴图渲染

1. 在本地开发服务器上真问一次，存下完整的流式回答（`a6.sse`）。挑问题：多问几个，选回答短、干净、能接上后面画面的那个。那次选了 “Is this lake real?”，57 个词，结尾正好说到“湖边四个地方”。每问一次，网站的匿名日志里就多一条，交付时说一声。
2. 用无界面 Chrome 打开真网站，把网站自己的对话组件铺满视口（尺寸按网站在 1920 宽屏幕上给它的大小，再乘 2.5 倍清晰度），把请求换成按片子时间回放的那份回答，按片子的帧逐帧截图。打字用浏览器的输入事件，悬停用真的鼠标事件，组件里的动画暂停后按片子时间设定。相同的画面只存一张，另存一份“哪一帧用哪张”的表。脚本：`capture_chat.mjs`、`cdp.mjs`。
3. 截图里没有输入框的光标，要自己画上：打字时常亮，停下后每 0.53 秒闪一次，打出空格后要往后挪一个空格宽。脚本：`make_board.py`。
4. 渲染时把画板那块面换成这张贴图：普通材质加一点自发光（0.55），受同样的黄昏光照，带景深，近看字很清楚。每帧按表换贴图。
5. 鼠标指针在后期叠加，位置用渲染那一帧的镜头参数把画板上的点投影到画面上，不会和画板错开。

## 天气：做成几何体渲染进去，第一版就要做全

- 雪和雨是一团点，用几何节点在每个点上放一片雪花或一根雨丝，按场景时间往下落，到底再从顶上出来。不打开物体自己的运动模糊，镜头的运动模糊已经足够把雨拉成线。
- 这种按时间变化的几何每一帧都要重建，那次每帧多花约 3 秒：只在它那一段前后打开。
- **每个地方的天气在开渲前列清楚，一样都不能少。** 那次漏了于田的沙尘，成片出来才发现；要补就得再租机器重渲那几秒。

## 首尾和合成

- 开场和结尾用网站自己的样子：深色底、字标、加载圆环，圆孔打开到开场画面，结尾收回同一个画面。结尾的画面就是开场的机位，首尾自然接上。
- 地名用原来那几支片子的写法：小字地名加一句斜体（where I was born. 等），在经过时刻前 0.85 秒出现，后 0.95 秒消失。
- 音乐用户剪好的就不动，只加淡入淡出；编码后真峰值超过 0 dB 时加一道限幅（那次压到 -1 dBTP），响度几乎不变。
- 脚本：`compose.py`，读逐帧 PNG，出 1080p 和 1440p 两个文件。

## 渲染和账

- 2560×1440，128 采样，镜头逐帧打关键帧加真实运动模糊（快门 0.5）。读字那段镜头基本不动，每帧因为换贴图多 2 到 3 秒。
- 1860 帧，5 台单卡机（3 台 RTX 4090、2 台 L40S）约 1 小时，连搭场景和试渲共 7.25 美元。多台机器的做法见 [出片](film.md) 的“云上多台机器”，命令是 `likeness fleet`。
- 每秒一段，近无损的 RGB 编码取回本地，再解成 PNG 合成。母版留着，以后改字幕、换音乐都不用重渲。

## 顺序

1. 看原片和成品要求，认清是不是“回场景重拍”这一类。
2. 分析音乐，写镜头路线，打印每 0.25 秒的速度和朝向自查。
3. 截真实界面，做贴图表。
4. 租一台机器重建场景，渲十几张正式画质的关键帧拼总览图，看构图、画板亮度、穿树的地方。
5. 低清整条（960 宽、16 采样、每 3 帧一张）分给几台机器渲，合成带音乐的 20 帧小样，看节奏和遮挡。
6. 正式渲染，合成，交付。
