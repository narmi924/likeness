# 好看和真实

## 先诊断

画面平、假、像游戏截图的时候，按这个顺序找原因：

1. **光有没有方向。** 没有方向的白天光会把所有东西压平。先定一个时间（那次选了黄昏），让太阳从侧面或逆光打过来。
2. **近处的东西是不是真的。** 镜头几米内的地面、草、树、石头决定了第一印象。
3. **东西和地面接触的地方。** 柱脚、墙根、树根有没有陷进去一点，有没有脏、有没有影子。
4. **远近有没有层次。** 远处要比近处淡、偏天空的颜色。
5. 最后才是材质细节和后期。

原来那个实时场景的六个毛病，每一个都对应上面某一条：山像白石膏（没有侧光和雪线）、楼是方盒子（没有窗和进深）、水是纯镜子（没有波纹）、草是几丛大尖片（近处不是真东西）、路面贴图被拉糊（贴图比例不对）、光没有方向。

## 现成的光和空气

下面几节讲的做法，通用的部分已经做成函数，在 `scripts/modeling/outdoor.py`：

```python
from modeling import outdoor
light = outdoor.sky(hdri, sun_azimuth=115)        # preset="dusk"（默认）、"day"、"overcast"；数值可逐项覆盖，如 sun_elevation=12
outdoor.haze(light, density=0.0004)               # 小场景用 0.0003 到 0.0006，几公里的大景用 0.0002
outdoor.film_settings(width=1920, samples=96)
```

- `sun_azimuth` 是太阳的方位（度，从 +X 逆时针，+Y 是北）。**太阳放在行进方向的侧面或侧前方**，影子横在路上、树干有明暗；正对着太阳走，地面一片反光，东西都成了剪影。
- `haze` 要在所有材质都建好之后调用。
- 调完先渲一张看曝光：地面最亮的地方还有纹理，暗处的树干还看得出形状。偏亮偏暗改 `scene.view_settings.exposure`。
- 辉光和暗角那次是在合成器里加的，函数里没有；要的话在最后的成片上做。

## 试做栈桥时学到的

用这个 skill 做过一个小题（黄昏走向湖边栈桥，6 秒）。五轮里改掉的都是会反复遇到的事：

- **扫描的草地在暖光下像枯草。** 给 `outdoor.ground` 加 `tint=(0.5, 0.66, 0.36)`。
- **浅色碎石在低太阳下糊成一块白斑。** 加 `path_tint=(0.6, 0.56, 0.5)`，路直接通到要去的地方（桥头、门口），不要在半路结束。
- **水边要有过渡。** `shore=` 给一圈湿沙，水线上摆几块石头，浅水里立几丛草。草地直接切进水里是假的。
- **远处的树林要密。** 一百多棵稀稀拉拉地站着像果园。水边那一排要挤（那次对岸 600 棵，间距两三米），往后可以稀。
- **镜头看得到的方向，地平线都要封住。** 湖要有对岸，也要有尽头；岸上一片草地平到天边同样是假的，后面要有树。
- **同一种植物等距重复像种的。** 草用几种大小混着撒，蕨这类叶形显眼的只放很少。细瘦的小树单独立在空地上很假，要么成丛要么不要。
- **想让整段都是黄昏的颜色，太阳要进画面附近。** 太阳在停靠画面中心左右 30 度以内，天边的暖色和水面的反光才在画面里；太阳在身后时，前面的天是冷蓝的，像阴天上午。曝光同时压低一档（`exposure=0.12`）。
- **停靠点退后一步。** 贴得太近时主体的近端被画面底边切掉，也看不到它和岸怎么接上。

两轮评审之后还留着、下次要先解决的：

- **背对太阳的那半边天是蓝的。** 素材库里那张黄昏天空，太阳一侧是橙色，另一侧是白云蓝天。镜头朝那边看时像上午（评审给开头 4.5 分、朝着太阳的结尾 7 分）。路线尽量安排成一路都朝着太阳这半边；必须背对太阳走的路段，换一张整片天都暗下来的天空图，或者把那一段的天空压暗调暖。湖那条片子有同样的问题。
- **镜头脚下的草盖不住地面。** 每平方米四五丛草，近看是一丛一丛等距立在糊掉的地面上。镜头两三米内要密到看不见地面（每平方米几十丛，只撒路边窄窄一条），或者让路边是石头、落叶这类本来就该露出地面的东西。
- **水面像镜子。** 黄昏的静水可以很平，但桩脚和船边要有一圈圈波纹，否则东西像插在玻璃上。
- **重复的零件太齐。** 一排木桩一样粗、一样圆、一样高就是假的。每根的粗细、歪斜、顶面都要不同，近处的两根要有裂纹和缺口。

## 那次的光（黄昏）

这些数值来自湖那条片子的渲染脚本（只在作者本机，不随 skill 分享）；`outdoor.sky` 和 `outdoor.film_settings` 已经按它们设好默认值。

| 项目 | 做法 |
|---|---|
| 天空 | Poly Haven 的黄昏天空图（evening_road_01_puresky），转到让图里的太阳和场景里的太阳同一个方位 |
| 太阳 | 单独一盏太阳灯，高度角 6 度，暖色 (1.0, 0.57, 0.28)，角直径 1.5 度。天空图里自己的太阳亮度压到 6 以下，不让它产生噪点 |
| 太阳周围 | 天空在太阳方向乘一层金色，地平线一条淡淡的暖带 |
| 看得见的太阳 | 一个只对镜头可见、不照亮任何东西的发光圆盘，给迎着落日的镜头用 |
| 色彩 | AgX，Medium High Contrast，曝光 0.42 |
| 后期 | 很轻的雾状辉光（0.3）和暗角（0.28），在合成器里做 |
| 人造光 | 沿路 26 盏矮路灯，建筑里约三分之一的房间亮着灯。黄昏里有暖色的点才有人气 |

不同天气的路段（那次有下雪的一段和下雨的一段）：

- 那一段头顶换成阴天的天空图，用两道只挡太阳直射、镜头看不见的竖墙做出云的影子。墙脚渐隐让地上的阴影边缘是软的，墙顶渐隐让高处的山峰仍然被太阳照到。
- 曝光跟着人走进暗处自动提高（雪 +0.36，雨 +0.7）。
- 积雪、湿地面和水洼渲在片子里：雪落在朝上的面上，雨在平地上留水洼。飘落的雪花和雨丝不渲，交给网页。

## 空气

- 远处变淡这件事做在材质里（一个共用的节点组，按离镜头的距离混入天空色），不用体积雾。这样水里的倒影也带着同样的雾，渲染也快。见 `lib_scene.py` 的 `make_haze_group`。
- 雾随高度变薄，雪山的山脊在雾蒙蒙的山脚上面仍然清楚。
- 朝太阳的方向雾偏暖，背对太阳偏冷。

## 素材

- **近处的植物、石头、地面贴图用扫描素材。** 那次全部来自 Poly Haven（CC0）：4 种树、草和蕨、3 组石头、7 种地面。
- **先看本机的素材库。** `likeness library` 列出已经下载过的素材（树、灌木、草、石头、地面贴图、黄昏和阴天的天空）和它们的路径，直接用，不用再下。模型用 `assets.import_model(path, target_size)` 导入，贴图文件夹用 `assets.pbr_material(folder)`。
- **库里没有的再找**：`python <skill>/scripts/sources.py search polyhaven "birch" --kind models`，然后按 `likeness library` 结果里 `add` 那一行的写法下载进素材库，别的项目以后也能用。
- **山用真实高程数据。** 那次的雪山来自 SRTM。沙丘、山谷这种地形按它的成因来做（风向、长缓坡和短陡坡），不要用一团噪声。
- **同一种树要有变化。** 高矮、转向、色相各不相同；秋天的胡杨、落了叶的树、挂雪的云杉是同一个模型调出来的（`build_loop_scene.py` 的 `tree`、`bare`、`snowy`）。
- 素材的季节、地域要和地方对得上。
- 每个素材在 `sources.md` 里记一行来源。

## 材质

- **地面**：几种扫描贴图按位置混合，先把它们的平均颜色调到一致，远近的地面才不会一块一块的。路是碾压过的碎石，路边有落叶和成丛的草。
- **水**：不是镜子。加一层很轻的波纹（凹凸强度 0.22），岸边露出石头和泥沙。
- **建筑外墙**：按物体自己的米数排窗格（层高 3.4 米、开间 3 米），无论楼怎么转格子都跟着走。一部分窗亮灯。墙上有雨痕、大片的污渍、靠近地面的一条脏带（`scene_parts.py` 的 `facade`、`weather`）。
- **玻璃**：要么是深色反光玻璃加亮灯的房间，要么是透明玻璃且后面真的有东西。平的深色格子最假。
- **新旧不搭**：从旧工程拿来的干净模型放在扫描素材旁边会显得太干净。给它加风化、重新打光，或者放远。
- **照片和画面**：哑光相纸带白边，贴在有厚度的板上，自身微微发光（0.04）让它在黄昏里还看得清。

## 渲出来以后自己先看

每一轮都渲真图看，不靠想象。看的时候逐条问：

- 缩成拇指大小，还认得出主体是什么吗？
- 影子有方向吗？边缘软硬对不对？
- 镜头前几米的地面：贴图有没有重复、拉伸、一片纯色？
- 东西落地的地方：有没有悬空、有没有一条生硬的线？
- 有没有能看出尺度的东西（门、台阶、路灯、椅子）？
- 玻璃后面有进深吗？
- 同一棵树是不是连着出现、朝向一样？
- 天空和太阳方向对得上吗？地平线是不是一条光秃秃的直线？
- 哪一块明显比别处“干净”或者“粗糙”？

## 看图把关

自己做的东西自己看不出毛病。那次两次请了只看渲染图、不知道制作过程的评审，照它的意见改了三轮，抓出了大部分问题：雪山加了前山和侧光，建筑改成正对停靠点并加了风化和亮灯的窗，照片改成带白边的哑光相纸，沙丘做出了脊线，地面加了落叶和成丛的草，小路换成碾压碎石，四个停靠点重新取景。

做法：

1. 准备图：关键位置的总览图（`likeness sheet`），加上三到六张原尺寸的单帧。
2. 另起一个评审。在 Claude Code 里用 Agent 工具开一个新的子代理，在 Codex 里开一个新的子会话。**用手头最强的模型**。
3. 只给它图和一句话的用途。**不给**制作过程、用了什么工具、你改过什么、你自己觉得哪里好。
4. 让它回答下面的问题。
5. 照它排在前面的几条改，同一批位置重新渲。
6. 第二轮换一个新的评审，不让它看到上一轮的意见。
7. 两轮之后，剩下的问题里选影响最大的告诉用户。

给评审的话，照这个写：

```text
这些图来自一段用 3D 做的片子：<一句话说它是什么、给谁看，例如“黄昏时沿湖边小路走一圈，网站访客滚动鼠标前进”>。
你只看画面，不用管它是怎么做的。请读这些图：<图的绝对路径，一行一个>

请回答：
1. 哪些地方一眼看上去是假的或者粗糙的？说出是哪张图的哪个位置，以及是什么让它显得假。
2. 最影响观感的三个问题，按严重程度排。
3. 每个停下来的画面，主体清楚吗、位置好吗？有没有东西挡着或者抢了注意力？
4. 相邻的图之间，光、颜色、气氛有没有对不上的地方？
5. 哪些地方做得好，不要动。

每一条都说“画面里看到了什么”和“改成什么样会更好”。不要泛泛的评价。
```

评审说的不一定都对，但它指出的位置几乎都值得再看一眼。不同意的条目记下原因，不要悄悄跳过。
